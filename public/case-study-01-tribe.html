Current platforms prioritise short-term attention. The gap: long-term trust.

The market is saturated with engagement-first products. The unmet need was safer connection, matched on intent instead of identity.

The brief was an intent-based social network for Budapest. The real brief, once I’d mapped the competitors, was: how do you get someone to type what they actually want — the uncurated version — into a field connected to a stranger-matching algorithm?

That’s a trust problem before it’s a product problem. It shaped every design decision that followed.

Full IA. Not everything survived the dev sync.

Three generations of input validation designed — two cut after synching with developers on latency, token cost, and structural reliability. What shipped earned it. The rest of the architecture: match logic, processing states, and safety exits, was built around the system that survived.

Input validation — three generations

Gen 1 — Cut
Manual tags

Freeform. No structure. System can’t match on noise.

Gen 2 — Cut
AI metadata extraction

Smarter — but unreliable JSON, 1.4s latency, 25× token cost.

Gen 3 — Shipped
Chip validation

NLP parses What / When / Where in real time. Hard to build. Worth the fight.

Why Gen 2 diedAfter synching with devs
Structural unreliability System expects {"tags":["x","y"]}. LLM returns conversational text. Fatal parse error. Every call needs a retry wrapper — just to extract two words.
Latency 800ms standard + 600ms metadata extraction = 1.4s wait before anything useful happens.
Token cost 15-word prompt + 400-token system prompt to classify it. 25× more to categorise than to process. Not viable for an MVP budget.

Why I pushed for Gen 3

Chips are harder to build. I pushed for them because match quality is the entire product bet. Vague input → bad matches → no Tribe. The chips are the quality gate that makes everything downstream worth building.

The decisionChose Gen 3 — real-time NLP chip validation over Gen 2 — AI metadata extraction, because match quality is the entire product bet: vague input, bad matches, no Tribe. Cost: harder to build, and the only generation that survived the dev sync.

One chat at a time — but what happens when the user wants to leave?

No chat search, one active conversation. The constraint is intentional: users in one chat take it more seriously. When choices are limited, people value what they have. The Breathe Chat (24h pause) and Safety Exit are the pressure valves — without them, a single-chat system becomes a trap. The constraint only works because the exits are designed in. A deliberate bet against dopamine loops — no infinite scroll, no variable reward.

What I’d do differently. What I’d do the same.

Send a questionnaire before any screen was drawn. Real user intent data would have sharpened the input validation from day one.

Push back on anything that doesn’t serve the user. Every constraint that survived the dev sync survived because it had a human reason behind it.

One metric: prompt quality in correlation to match quality. That correlation — or the absence of it — would tell me whether the core thesis holds.

Phase 1 — UsabilityPre-Launch Lab Testing Phase 2 — TelemetryAlpha Field Testing
Objective Verify if real-time keyword highlighting reduces input anxiety and ensures semantic accuracy. Validate the NLP matching engine and progressive disclosure mechanics under live infrastructure load.
Methodology Moderated testing (8–10 participants) using low-fidelity click-dummies. 14-day unmoderated field test deployed to a high-density cohort of 500–1,000 target users in Budapest.
Signals Time-on-task, token correction frequency, and subjective workload (SEQ score). Progress toward the target ≥40% match-to-meetup conversion milestone, live data logging against the <40% engine failure threshold, and exact drop-off points within the unmasking sequence.
